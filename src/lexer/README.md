д# Лексический Анализатор (Lexer)

Лексический анализатор, или лексер (также известный как сканер или токенизатор), является первым этапом работы компилятора. Его основная задача — преобразовать последовательность символов исходного кода в последовательность *токенов*.

## Что такое Токен?

Токен — это объект, представляющий собой минимальную значимую единицу языка. Например, ключевое слово `function`, идентификатор `myVariable`, число `42` или оператор `+` — все это токены.

Каждый токен обычно имеет два основных атрибута:
1.  **Тип (Type):** Категория токена (например, `KEYWORD`, `IDENTIFIER`, `NUMBER_LITERAL`, `OPERATOR`).
2.  **Значение (Value/Lexeme):** Фактическая текстовая строка из исходного кода, которая соответствует этому токену (например, `"function"`, `"myVariable"`, `"42"`, `"+"`).

## Как работает наш Лексер?

Наш лексер, реализованный в `src/lexer/lexer.ts`, последовательно читает исходный код и сопоставляет его с набором предопределенных правил, описанных с помощью регулярных выражений.

Процесс работы выглядит так:
1.  Лексер пытается сопоставить начало оставшейся части исходного кода с каждым из известных ему шаблонов токенов.
2.  Шаблоны имеют приоритет. Например, шаблон для ключевого слова `if` будет проверяться раньше, чем шаблон для обычного идентификатора. Это гарантирует, что `if` будет распознан как ключевое слово, а не как переменная с именем "if".
3.  Когда совпадение найдено, лексер "отрезает" совпавшую часть строки (лексему) от исходного кода, создает объект токена с соответствующим типом и значением и добавляет его в список.
4.  Пробелы, символы табуляции и переносы строк обычно игнорируются, так как они не несут смысловой нагрузки на этом этапе.
5.  Этот процесс повторяется до тех пор, пока весь исходный код не будет обработан.
6.  Если лексер встречает последовательность символов, которую не может сопоставить ни с одним из шаблонов, он генерирует ошибку, сообщая о неизвестном символе в коде.

В результате работы лексера мы получаем плоский список токенов, который затем передается на следующий этап компиляции — синтаксический анализ (парсинг).
