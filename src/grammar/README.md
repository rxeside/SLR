# Грамматика Языка

Директория `src/grammar` содержит определение формальной грамматики нашего языка программирования. Грамматика — это набор правил, которые описывают, как должны выглядеть синтаксически корректные программы. Наш парсер использует эту грамматику для проверки кода и построения AST.

## Формат Правил

Грамматика представлена в файле `src/grammar/grammar.ts` в виде набора *правил вывода* (productions). Каждое правило имеет вид:

`A -> B C D ...`

Это означает, что синтаксическая конструкция `A` (называемая *нетерминалом*) может состоять из последовательности символов `B`, `C`, `D` и т.д. Эти символы могут быть как *нетерминалами* (другими, более мелкими конструкциями), так и *терминалами* (токенами, поступающими от лексера).

**Пример:**

Правило `VariableDeclaration -> LET Identifier COLON Type SEMICOLON` описывает, как в нашем языке объявляется переменная. Оно говорит, что объявление переменной (`VariableDeclaration`) состоит из:
1. Ключевого слова `let` (токен `LET`).
2. Имени переменной (токен `Identifier`).
3. Двоеточия (токен `COLON`).
4. Типа переменной (конструкция `Type`).
5. Точки с запятой (токен `SEMICOLON`).

## Стартовый Символ

У каждой грамматики есть *стартовый символ* — самый общий нетерминал, который представляет всю программу. В нашем случае это, как правило, `Program`. Задача парсера — доказать, что вся последовательность токенов исходного кода может быть "свернута" до этого стартового символа. Если это удается, программа синтаксически корректна.

## Роль в Компиляторе

Грамматика — это "чертеж" языка.
- **Для парсера:** Она является источником правил для проверки синтаксиса. Инструменты (в нашем случае, скрипт, генерирующий таблицы для SLR-парсера) анализируют эту грамматику и создают на ее основе таблицы действий и переходов, которыми руководствуется парсер.
- **Для разработчика компилятора:** Она служит формальной спецификацией языка. Чтобы добавить в язык новую конструкцию (например, цикл `for`), необходимо сначала добавить соответствующее правило в грамматику, а затем научить остальные части компилятора (построитель AST, семантический анализатор, генератор кода) работать с этой новой конструкцией.
