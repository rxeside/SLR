# Семантический Анализатор

Семантический анализ — это третий этап компиляции, следующий за синтаксическим анализом. Если парсер проверяет, *правильно ли написана* программа (синтаксис), то семантический анализатор проверяет, *имеет ли она смысл* (семантика).

На этом этапе компилятор проверяет программу на наличие ошибок, которые невозможно обнаружить на уровне синтаксиса. Основная задача — убедиться, что все конструкции языка используются в соответствии с правилами типов и областей видимости.

## Основные Задачи Семантического Анализатора

В нашем компиляторе (`src/analyzer/analyzer.ts`) анализатор выполняет следующие проверки:

1.  **Проверка объявлений:**
    -   Убеждается, что каждая используемая переменная или функция была объявлена перед использованием.
    -   Запрещает повторное объявление переменной или функции в одной и той же области видимости.

2.  **Проверка типов (Type Checking):**
    -   Проверяет совместимость типов в операциях. Например, нельзя складывать число со строкой (если язык этого не позволяет).
    -   Убеждается, что тип значения, присваиваемого переменной, соответствует объявленному типу переменной.
    -   Проверяет, что тип возвращаемого значения в функции соответствует ее объявленному возвращаемому типу.

3.  **Проверка вызовов функций:**
    -   Проверяет, что вызываемый идентификатор действительно является функцией.
    -   Сверяет количество переданных аргументов с количеством ожидаемых параметров.
    -   Проверяет типы переданных аргументов на соответствие типам параметров функции.

## Обход AST и Паттерн "Посетитель" (Visitor)

Для выполнения этих проверок анализатору необходимо обойти все узлы Абстрактного Синтаксического Дерева (AST). В нашем проекте для этого используется паттерн проектирования **"Посетитель" (Visitor)**.

-   `SemanticAnalyzer` реализует интерфейс `ASTVisitor`.
-   Для каждого типа узла AST (`BinaryExpr`, `VariableDeclaration`, `FunctionCall` и т.д.) в анализаторе есть соответствующий метод `visit...` (например, `visitBinaryExpr`).
-   Обход дерева начинается с вызова метода `visit` для корневого узла. Этот метод, в свою очередь, рекурсивно вызывает `visit` для всех дочерних узлов, обеспечивая полный обход дерева.
-   Внутри каждого `visit...` метода реализуется логика семантической проверки, специфичная для данного узла.

## Таблица Символов (Symbol Table)

Ключевым инструментом для семантического анализа является **Таблица Символов** (`src/symbolTable/symbolTable.ts`). Это структура данных, которая хранит информацию обо всех идентификаторах (именах переменных, функций) в программе.

-   **Отслеживание объявлений:** Когда анализатор встречает узел объявления (`VariableDeclaration`, `FunctionDeclaration`), он добавляет информацию о новом символе (имя, тип, категория) в таблицу символов.
-   **Проверка использования:** Когда анализатор встречает узел использования символа (например, `Identifier` в выражении), он ищет этот символ в таблице, чтобы убедиться, что он был объявлен, и чтобы получить информацию о его типе.
-   **Управление областями видимости (Scopes):** Наша таблица символов поддерживает иерархию областей видимости. Когда анализатор входит в новый блок кода (например, тело функции или цикла), создается новая, дочерняя область видимости. Это позволяет корректно обрабатывать локальные переменные и затенять (shadowing) переменные из внешних областей. При выходе из блока дочерняя область видимости уничтожается.
