# Prima Virtual Machine

Запуск машины
PVM.exe {путь до файла}
PVM.exe example1.prmbc

---

## 🧮 Типы данных (`Value`)

Все значения в PVM представлены типами:

| Тип              | Описание                         |
|------------------|----------------------------------|
| `Null`           | Пустое значение                  |
| `int`            | Целое число                      |
| `double`         | Число с плавающей точкой         |
| `bool`           | Логическое значение (true/false) |
| `String`         | Строка                           |
| `Function`       | Функция                          |
| `NativeFunction` | Нативную функцию                 |
| `Array`          | Массив                           |
| `Class`          | Класс                            |
| `Instance`       | Экземпляр класса                 |

> Все значения могут быть положены на стек.

## ⚙️ Опкоды

### 🔢 Арифметические и логические операции

В описании стека справа будет вершина.

---

### `add`

- **Стек до**: `y, x`
- **Стек после**: `x + y`
- **Описание**:
  - Складывает два значения.
  - Поддерживает: числа, строки, массивы.
    - Для чисел: обычное сложение.
    - Для строк: конкатенация.
    - Для массивов: объединение двух массивов.

---

### `sub`

- **Стек до**: `y, x`
- **Стек после**: `x - y`
- **Описание**:
  - Вычитает `y` из `x`.
  - Работает только с числами.

---

### `mul`

- **Стек до**: `y, x`
- **Стек после**: `x * y`
- **Описание**:
  - Умножает `x` на `y`.
  - Работает только с числами.

---

### `div`

- **Стек до**: `y, x`
- **Стек после**: `x / y`
- **Описание**:
  - Делит `x` на `y`.
  - Если `y == 0`, выбрасывается ошибка "Divide by zero".
  - Работает только с числами.

---

### `mod`

- **Стек до**: `y, x`
- **Стек после**: `x % y`
- **Описание**:
  - Возвращает остаток от деления `x` на `y`.
  - Работает только с целыми числами.

---

### `neg`

- **Стек до**: `x`
- **Стек после**: `-x`
- **Описание**:
  - Применяет унарный минус к значению.
  - Работает только с числами.

---

### `ceq`

- **Стек до**: `y, x`
- **Стек после**: `x == y`
- **Описание**:
  - Сравнивает `x` и `y` на равенство.
  - Возвращает `true` или `false`.

---

### `cgt`

- **Стек до**: `y, x`
- **Стек после**: `x > y`
- **Описание**:
  - Сравнивает `x` и `y` на больше.
  - Возвращает `true` или `false`.

---

### `clt`

- **Стек до**: `y, x`
- **Стек после**: `x < y`
- **Описание**:
  - Сравнивает `x` и `y` на меньше.
  - Возвращает `true` или `false`.

---

### `not`

- **Стек до**: `x`
- **Стек после**: `!x`
- **Описание**:
  - Применяет логическое НЕ к значению.
  - Преобразует значение в `bool`.

---

### `and`

- **Стек до**: `y, x`
- **Стек после**: `x && y`
- **Описание**:
  - Логическое И с коротким вычислением:
    - Если `x` — false, возвращается `x`.
    - Иначе возвращается `y`.

---

### `or`

- **Стек до**: `y, x`
- **Стек после**: `x || y`
- **Описание**:
  - Логическое ИЛИ с коротким вычислением:
    - Если `x` — true, возвращается `x`.
    - Иначе возвращается `y`.

- **Стек после**: `array`
- **Описание**:

---

- **Стек после**: —
- **Описание**:

## Upvalues

PVM для реализации замыкания использует так называемые upvalues.
Upvalue по своей сути - локаль, которую мы захватили у родителя.
Функция имеет две опциональные директивы: `.parent_local` и `.parent_upvalue`

В `.parent_local` мы указываем индексы локалей родителя, которые хотим у него захватить.

Рассмотрим пример:

```
const a = 1;
const b = 2;
const c = 3;

function addA(b)
{
    return b + a + c;
}

println(addA(2));
```

Байткод для него будет выглядеть вот так:

```
.def
.argc 0
.locals 4
.name __EntryPoint__
.constants
number 1
number 2
number 3
string println
.code
1 const 0
1 set_local 0
2 const 1
2 set_local 1
3 const 2
3 set_local 2
10 load_fn 1
10 closure
10 set_local 3
10 const 1
10 get_local 3
10 call 1
10 get_global 3
10 call 1
10 pop
10 return
.end_def


.def
.argc 1
.locals 0
.name addA
.parent_local 0 2
.code
7 get_local 0
7 get_upvalue 0
7 add
7 get_upvalue 1
7 add
7 return
.end_def

```

Мы видим, что функция addA захватывает у родителя переменные `a` и `c`. 
Переменные эти лежат в локалях 0 и 2 соответственно. Поэтому в объявлении функции мы видим директиву с индексами `.parent_local 0 2`.


Однако, возможен случай, когда нам нужно захватить переменные не у родительского контекста, а у родительского контекста родительского контекста.
У так называемого "дедова" контекста. Для таких случаев существует директива `.parent_upvalue`, в которой мы указываем индексы родительских upvalue,
которые по сути являются захваченными локалями его родителя.

Рассмотрим пример:
```
const z = 1;
const x = 2;
const a = 3;

function addA(b)
{
    function addB()
    {
        return a + b;
    }

    return addB();
}

println(addA(2));
```

Для него получим вот такой байткод:
```
.def
.argc 0
.locals 4
.name __EntryPoint__
.constants
number 1
number 2
number 3
string println
.code
1 const 0
1 set_local 0
2 const 1
2 set_local 1
3 const 2
3 set_local 2
15 load_fn 1
15 closure
15 set_local 3
15 const 1
15 get_local 3
15 call 1
15 get_global 3
15 call 1
15 pop
15 return
.end_def


.def
.argc 1
.locals 1
.name addA
.parent_local 2
.code
12 load_fn 2
12 closure
12 set_local 1
12 get_local 1
12 call 0
12 return
.end_def


.def
.argc 0
.locals 0
.name addB
.parent_local 0
.parent_upvalue 0
.code
9 get_upvalue 1
9 get_upvalue 0
9 add
9 return
.end_def

```

Мы видим, что функция `addB` захватывает 2 переменные: `b` у родителя и `c` у так называемого `деда`.
`b` у родителя является локалью с индексом `0`, поскольку это первый параметр функции.
`a` у родителя является upvalue с индексом `0`, поскольку это первое захваченное значение.
Захватывает он его у родителя, а у родителя эта переменная является третьей (локаль с индексом `2`).
Поэтому в функции addA мы видим `.parent_local 2`. И затем уже это upvalue захватит `addB`.
